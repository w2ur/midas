# Safety rails, currency and units

Moved out of `CLAUDE.md` on 2026-08-23 — these three lines were the densest
money-path text in the file. Nothing was cut; the guards stayed behind as stubs.

## The broker refuses implausible numbers, not just ill-formed ones

- `engine/paper_broker.py` — Hands side: 19 rejection/cancel reason codes + fill logic + portfolio update. Since 2026-08-07 the broker can refuse an implausible number, not just an ill-formed one: `PRICE_IMPLAUSIBLE` (fill outside [1/5, 5]x the prior close on a BUY / the position's `avg_cost` on a SELL), `TRIGGER_LEVEL_IMPLAUSIBLE` (conditional level outside [0.2, 5.0]x the latest close, refused **at intake** so it never arms), `CURRENCY_UNRESOLVED` (no layer can denominate the ticker) and `VALUATION_UNAVAILABLE` (the book will not value, so its relative rails cannot be evaluated — an unevaluated rail is not a passed rail). The bands are deliberately loose: they target unit/basis errors, which arrive as a factor of 100, not market moves. `tests/test_rails_live_coverage.py` replays the whole committed ledger against them (216 fills, all within 0.91–1.07x) so a tightened band cannot start refusing real trades unnoticed

## Ticker to currency, and why units are not currencies

- `engine/quotes.py` — ticker → currency resolution + price reads. Three layers, in order: the `data/ticker_currencies.json` override map, the vendor's own answer captured into `data/tickers.json` by `scripts/fetch_ohlcv.py`, then a suffix heuristic. A suffix cannot answer the question (`LLOY.L` quotes in pence, `PHAG.L` in USD, and a currency pair quotes in its *second* leg). **Since 2026-08-07 the heuristic returns `None` for a suffix it does not enumerate** instead of defaulting to USD — the fourth failure mode of the quote-currency defect, and the one with no symptom, since a wrong currency still prices. `ticker_currency`, `store_quote`, `latest_price` and `normalise_vendor_quote` are therefore all Optional; the broker turns `None` into `CURRENCY_UNRESOLVED`. A bare ticker keeps USD (Yahoo's US-listing convention, not a guess). `tests/test_rails_live_coverage.py` asserts every **held or pending** ticker resolves from layers 1–2 — not the heuristic — while universe tickers need only resolve to something (130 of 1,046 legitimately sit on the suffix table today). **`GBp` is a unit, not a currency**, and since 2026-08-07 **the store is ISO-denominated**: the pence→pounds division happens ONCE, at ingest, in `scripts.fetch_ohlcv._normalise_vendor_units`. `vendor_quote_unit` returns the vendor's raw unit (ingest + registry only), `ticker_currency` the ISO code, `normalise_vendor_quote` converts a *vendor* price, and `store_quote` attaches a currency to a *stored* price without scaling. Read paths must never scale — doing so divides every LSE price by 100 twice. Mirrored on the site in `site/src/lib/ohlcv.ts`. The migration of the 128 pence files already in the store is `scripts/normalise_store_units.py`, guarded by a marker file because a normalised store is indistinguishable by inspection from a pence one

## Per-agent rails in `roster.yaml`

- `roster.yaml` — the cast (agents, voices, schedule, universes, benchmarks, per-agent safety rails) + globals. **Trader rails recalibrated 2026-08-07**: `max_order_notional_pct: 30` (a *percentage of current book value*, which takes precedence over the absolute `max_order_notional` and re-scales as the book moves), `max_orders_per_day: 10`, `daily_drawdown_halt_pct: -15`. They were `1_000_000 / 100 / -95` on €10,000 books — a per-order cap 100x the whole portfolio. The allocator keeps its absolute `500 / 5 / -5`; forks setting only the absolute field are unaffected. the engine and orchestrator are config-driven from this file. Also declares `sentiment_arm: treatment` on the two agents in the pre-registered sentiment A/B — membership used to exist only as prose in the two persona files and in METHODOLOGY.md, so nothing could report which arm a session actually ran. Special roles: `role: narrator` (the Oracle) and `role: allocator` (the Manager) are declared here — the allocator block is opt-in (omit it to run with no allocator; multiple allocators are supported via distinct `channels_prefix` values). Set `MIDAS_DATA_DIR` to redirect all data reads/writes to a different root (e.g. for forks or isolated test runs).
